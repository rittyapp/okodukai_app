# おこづかい帳 v3 仕様書

このドキュメントだけ読めば、他のAIや開発者でも同等のアプリを作れることを目的にしています。
実装の細かい変数名・列名などは書いていません（`gas/Code.gs` の冒頭と各関数のコメントを参照）。
利用者が行う操作（デプロイ・初期設定など）は [README の「使い方」](../README.md#使い方) にまとめています。

---

## 1. どんなアプリか

- 子供が「お手伝いボタン」を押すと、親の承認待ちになる。親が承認すると残高に入る
- 子供は「つかったきろく」で使ったお金を記録する（承認不要ですぐ残高から引かれる）
- 親は承認・却下・編集・取消、残高調整、お手伝いボタンの編集、ユーザー管理を行う
- お手伝いを頑張った月は、翌月の初めに「月初ボーナス」が入る
- 親は Google アカウント、子供は4桁PIN（またはGoogleアカウント）でログインする

## 2. 構成（無料で作れる）

| 部品 | 役割 |
|---|---|
| GitHub Pages | 画面（HTML/CSS/JS の静的ファイル）。全家庭で共通 |
| Google スプレッドシート | データ保存。**家庭ごとに1つ**（各家庭の親のドライブ） |
| Google Apps Script（スプレッドシートにバインド） | JSON API。ウェブアプリとして「自分として実行・全員がアクセス可」で公開 |
| Google OAuth（IDトークン） | 親のGoogleログインの本人確認 |

- 画面は接続先（家庭ごとのApps ScriptのURL）を URL パラメータと端末に保存して使う。共有QRコードにも接続先が入る
- 通信は `text/plain` の POST（CORSの事前確認が起きない形）で JSON をやり取りする
- 日付を含むデータは文字列にしてから返す（Apps Script の `google.script.run` は Date を返すと結果全体が null になるため、v2 ではこれが原因で履歴や承認待ちが表示されなかった）
- 書き込みはスクリプトロックで直列化し、ボタン1回ごとに付ける一意のIDで二重登録を防ぐ

## 3. 画面

### 3.1 ログイン画面（子供・親で共通）

上から順に：
- アプリ名
- PIN入力の丸（4つ）
- **キーパッド 4行×3列**：`1 2 3 / 4 5 6 / 7 8 9 / 削除 0 ログイン`
  - 1つのキーは正方形。スマホでは画面幅と高さに合わせてバランスよく縮み、PCでは幅320px程度で止まる
  - PCのキーボードの数字・Backspace・Enterでも操作できる
- 「Googleでログイン」ボタン
- 「初期設定」ボタン（未設定・シート破損時のみ表示）
- 「共有QRコード」（押すと開く。接続先の変更もここから）とバージョン表記

ログアウトすると必ずこの画面に戻る。ログイン画面の要素は子画面・親画面には出さない（共有QRのタブは廃止）。

PINは端末（ブラウザ）単位で失敗回数を数え、3回で1分、6回で5分、10回で完全ロック。ロック中は正しいPINでも「ちがいます」とだけ表示する。完全ロックは、その端末で親がGoogleログインするか、親の設定タブで解除する。

### 3.2 子画面（タブ：きろく／カレンダー）

**きろく**
- 残高
- 「ボーナスを確認」（未処理の月初ボーナスがあるときだけ）
- 「ボーナス発生中」表示（お手伝いボタンの上）：昨日まで2日続けてお手伝いしている日、今日すでに2回した日
- お手伝いボタン（名前と金額）。押すとすぐ処理し、そのボタンは3秒ほど暗くなって押せない
- 1日の上限（3回）に達すると「親に追加をおねがいする」を表示
- つかったきろく（金額・内容）。押した瞬間に入力欄を空にし、ボタンを数秒押せなくする
- りれき：新しい順。申請中・承認済み・却下・取消すべて表示。**自分が押したもの**は申請中でも承認済みでも「取り消す」ができる
- 押した直後は通信を待たずに画面へ仮表示し、あとでサーバーの内容に置き換える（固まって見えないように）

**カレンダー**
- 月曜始まり。初期表示は今月。前の月へ移動でき、今月までは戻れる。未来の月へは進めない
- お手伝いした日は色付き、1日3回以上の日は別の色
- 日付をタップすると、その日の記録を一覧表示

### 3.3 親画面（タブ：承認待ち／ユーザー／設定）

**承認待ち**
- 申請中の一覧（古い順）。各行に「承認」「却下」「編集」
- 最近承認したもの（ボーナス含む）。各行に「編集」「取り消す」
- 編集：項目名・金額・日付（月と日のみ。年と時刻は元のまま、未来日は不可）。承認前でも承認後でもできる。メモに「（親の名前）編集済み」を追記

**ユーザー**
- 一番上にログイン中の親の名前
- 子供の一覧（残高付き）。各子供に「子の画面へ」「編集」
- ほかの親の一覧（編集可）
- 「ユーザー変更」フォーム：新規追加／既存ユーザーの名前・役割・メール・PIN・有効無効を変更。PINは表示しない（空欄なら変更しない）。親を0人にする変更はできない

**子の画面（親が開いたとき）**
- 子画面と同じ見た目に加えて、「← 親の画面へ戻る」「残高調整（マイナス可）」
- お手伝いボタンを親が押せる。押すと「その親が承認済み」として記録（上限なし）
- 「お手伝い編集」で編集モードになり、ボタンの名前・金額の変更、追加、削除ができる（削除は非表示にするだけで過去の記録は残る）
- りれきは全件に 承認／却下／編集／取り消す／未承認に戻す／非表示 を状況に応じて表示

**設定**
- スプレッドシートへ移動
- アプリ名とアイコン（絵文字＋背景色）の変更。変更後に作ったホーム画面のショートカットに反映
- PINロック端末：最近1か月に使われた端末を表示（0件なら最新3端末）。「解除する」ボタン。30件を超えた古い端末情報は自動で黙って削除
- 初期設定（シートの修復）：足りないシート・列を作り直し、重複したお手伝いIDなどを直す。データは消さない

## 4. ルール

### 4.1 記録の種類と状態

| 種類 | 作られ方 | 最初の状態 |
|---|---|---|
| お手伝い | 子供が押す／親が押す | 子供＝申請中、親＝承認済み |
| つかった | 子供／親が入力 | 承認済み（すぐ残高に反映） |
| 残高調整 | 親が入力 | 承認済み |
| 上限追加のおねがい | 子供が押す（1日1回） | 申請中。承認されるとその日は上限なし |
| 月初ボーナス | 「ボーナスを確認」 | 承認済み（承認者は「システム」） |

状態：申請中 → 承認済み／却下、承認済み → 取消（または未承認に戻す）。
残高は「承認済み」の金額の合計だけで計算する。却下・取消は30日後に自動で履歴から隠す（削除はしない）。

### 4.2 取り消しできる人

- 親：すべての記録（申請中・承認済み）
- 子供：**自分が押した／入力した**お手伝い・つかった・おねがい（申請中・承認済み）。親が入れたもの、ボーナス、残高調整は取り消せない

### 4.3 月初ボーナス

- お手伝いを押した時点では基本金額のみ。ボーナスは翌月にまとめて計算する（あとから取り消されたり、承認が取り消されたりするため）
- 子供（または親が子の画面）を開いたとき、**お手伝いをした過去の月でボーナス処理がまだの月**があれば「ボーナスを確認」を表示。押すと月ごとに1行ずつ記録する
  - 日付：その月の翌月1日
  - 項目：「○月ボーナス」、メモ：「○月ボーナス ○円（内訳）」
  - 0円でも記録する（処理済みの印になる）。親が取り消しても処理済みのまま
  - 2か月以上たまっていれば、その月数分の行ができる
- 計算対象：その月の「申請中」と「承認済み」のお手伝い（却下・取消は数えない）
  - 同じ日の3回目以降のお手伝い：1回につき +10円
  - 3日以上連続した日（前月からの連続も数える）のお手伝い：1回につき +10円
  - 両方当てはまれば両方加算
- 親は承認不要で入るボーナスを、編集（金額修正）または取り消し（却下扱い）できる

### 4.4 二重押し・処理落ち対策

- すべての書き込みボタンは押した後数秒押せない（暗く表示）
- 同じ操作が2回サーバーに届いても、1回分しか記録しない
- 画面は先に仮表示し、通信が遅くても操作を続けられる
- 通信は45秒でタイムアウトし、エラーを画面下に表示する

## 5. データ（スプレッドシート）

| シート | 内容 |
|---|---|
| Users | 親・子供（名前、役割、メール、PIN、有効/無効） |
| ChoreMaster | お手伝いボタン（名前、金額、有効/無効） |
| Ledger | すべての記録（1行1記録。お金の動き・申請・ボーナス） |
| PinDeviceState | PIN入力の失敗回数とロック状態（端末ごと、最大30行） |

アプリ名・アイコン・ログイン中のセッション・ボーナス開始月は Apps Script のスクリプトプロパティに保存する。

## 6. セキュリティの考え方

- 最初の親になれるのは、スプレッドシートの持ち主（Apps Scriptを実行しているアカウント）と同じGoogleアカウントだけ
- GoogleのIDトークンは、発行先（クライアントID）・発行元・メール確認済み・使い捨ての値（nonce）を検証する
- すべての操作はサーバー側でも権限を確認する（子供は自分の記録だけ、親専用の操作は親だけ）
- 個人情報（メール・PIN・スプレッドシートID・URL）はリポジトリに置かない

## 7. 変更履歴

| 版 | 主な変更 |
|---|---|
| v1 | Apps Script 内の画面。Googleアカウントの自動判定でログイン |
| v2 | 公開範囲を「全員」にし、Googleログイン（OAuth）と子供の4桁PINに対応 |
| v2.1 | 子画面のQRをタブ化、親の「履歴・入力」と「子供画面」を統合 |
| **v3** | 画面を GitHub Pages に移し、どの家庭でも自分のスプレッドシートで使えるように。ログイン画面刷新（正方形キーパッド・共有QR・バージョン）、親画面を3タブに整理、承認前後の編集、親による子の画面の操作とお手伝い編集、カレンダー、月初ボーナス、二重押し対策、アプリ名・アイコン変更、初期設定・修復ボタン、デモモード |

### v2 で「きろくが表示されない」「承認できない」原因（v3で解消）

1. 履歴・承認待ちの一覧に日付（Date型）が含まれており、`google.script.run` が結果を null にしていた。画面側は null の件数を読もうとして止まり、何も表示されなかった（残高は数値だけなので表示されていた）
2. お手伝いマスタに同じIDが2つずつあり（c11、c12）、「ひとりで買い物」を押すと「ひとりで料理」として記録されていた。v3 の初期設定（修復）で自動的にIDを振り直す

## 8. QA（指示の矛盾・相談したい点）

指示書を実装する中で、判断が必要だった点・実現できなかった点です。**★は回答をお願いしたいもの**、それ以外は仮にこう実装した、という記録です。

### ★Q1. Webからの完全自動セットアップはできない（相談）

- **要望**：最初の親がログインするだけで、スプレッドシート作成・スクリプト入力・初期化まで Web からすべて行う
- **制約**：GitHub Pages のページから他人のドライブにスクリプト付きスプレッドシートを作る・ウェブアプリとして公開するには、Apps Script API と Drive の「制限付き／機密」スコープが必要。これらは Google の審査（セキュリティ評価を含む場合あり、数週間〜）を通さないと一般公開できない。また、ウェブアプリの公開と権限の承認は、最後に持ち主本人が Apps Script の画面で行う必要がある
- **今の実装**：①原本スプレッドシートを「コピー」（ボタン1つ）②Apps Script で「デプロイ」（数クリック）③URLを貼り付け ④「初期設定」ボタン → シート作成・最初の親の登録は自動。README に手順を記載
- **相談**：この「コピー＋デプロイだけ手作業」で良いか。審査を受けて完全自動化を目指すか

### ★Q2. OAUTH_CLIENT_SECRET は不要になった

- **要望**：`OAUTH_CLIENT_ID` と `OAUTH_CLIENT_SECRET` をスクリプトプロパティで管理
- **実装**：画面が GitHub Pages に移ったため、Google から直接IDトークンを受け取る方式に変更。シークレットは使わない（ブラウザに置けない値なので、むしろ無い方が安全）。`OAUTH_CLIENT_ID` はスクリプトプロパティで上書き可能、未設定なら共通のIDを使う
- **相談**：共通のクライアントID（あなたの Google Cloud プロジェクト）を他の家庭も使う形で良いか。使う場合、OAuth 同意画面を「本番環境」に公開する必要があり、ログイン時にあなたのアプリ名・サポート用メールが表示される。嫌なら各家庭が自分でクライアントIDを作る手順に変える

### ★Q3. 既存データの9月分ボーナス

- 旧版はお手伝いを押した時点でボーナスを金額に上乗せしていた。9月分を月初ボーナスでも計算すると二重になるため、**既存のスプレッドシートは 2026年10月分からボーナスを月初計算**にした（新しい家庭は開始月から計算）
- 9月分も月初ボーナスにしたい場合は、スクリプトプロパティ `BONUS_START_MONTH` を `2026-09` にする（ただし9月の上乗せ分は手で直す必要あり）

### ★Q4. ボーナス計算に「申請中」を含めるか

- 月初時点で親がまだ承認していない「申請中」も数えている（承認が遅れて子供が損をしないように）。その後却下しても、ボーナスは自動では減らない → 親がボーナス行を編集する
- 「承認済みだけ数える」に変える場合は1か所の変更で済む

### Q5. ボーナスの数え方（仮にこう解釈）

- 「1日3回目」＝同じ日の3回目以降のお手伝い1回ごとに +10円（4回目も+10円）
- 「3日連続」＝連続3日目以降の日のお手伝い1回ごとに +10円。月をまたいだ連続も数える
- 「ボーナス発生中」は、昨日まで2日連続している日（今日すると3日目）と、今日すでに2回した日に表示

### Q6. 1日の上限（3回）と「追加をおねがいする」は残した

- 指示になかったため v2 の仕様を維持。親が子の画面で押す分は上限なし

### Q7. 子供が取り消せる範囲

- 「押した人間がすべて取り消しできる」→ 子供は自分が押したものを承認後でも取り消せる（残高が減る）。親が押したもの・ボーナス・残高調整は子供は取り消せない

### Q8. 「ユーザー変更」の意味

- 「ユーザーの追加・編集フォーム」と解釈した。別の意味（例：ログイン中のユーザーを切り替える＝ログアウト）なら教えてください

### Q9. アプリ名の変更とショートカット

- 変更後に「ホーム画面に追加」したものに反映。すでに追加済みのショートカットの名前は OS 側の仕様で変わらないため、作り直しが必要
- 各家庭は設定タブで絵文字＋色のアイコンを作れる。**リポジトリ標準のアイコン（`icons/`）は仮のブタのデザインなので、正式なアイコンのデザインをお願いします**

### Q10. 共有QRコードをログイン画面に置くこと

- ログイン前でも見られるが、QRに入っているのは「アプリのURL＋接続先」だけで、使うにはPINかGoogleログインが必要。問題があれば親画面に戻す

### Q11. 今動いている v2 からの移行

- v3 の Code.gs をデプロイすると、今の `/exec` URL は GitHub Pages の新画面へ自動転送される。家族は一度ログインし直しが必要
- 最初に親がGoogleログインしたとき、足りない列の追加・重複IDの修正が自動で行われる
- 新画面のGoogleログインには、README「C. 管理者がやること」のリダイレクトURI追加が先に必要
