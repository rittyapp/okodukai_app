# おこづかい帳 v3 仕様書

このドキュメントだけ読めば、他のAIや開発者でも同等のアプリを作れることを目的にしています。
実装の細かい変数名・列名などは書いていません（`gas/Code.gs` の冒頭と各関数のコメントを参照）。
利用者が行う操作（デプロイ・初期設定など）は [README の「使い方」](../README.md#使い方) にまとめています。

---

## 1. どんなアプリか

- 子供が「お手伝いボタン」を押すと、親の承認待ちになる。親が承認すると残高に入る
- 子供は「つかったきろく」で使ったお金を記録する（すぐ残高から引かれ、親が確認するまでは申請中）
- 親は承認・却下・編集、残高調整、お手伝いボタンの編集、ユーザー管理、各種設定を行う
- お手伝いを頑張った月は、翌月の初めに「月初ボーナス」、毎月決まった日に「定期おこづかい」が入る（どちらも子供の画面で押して受け取る）
- 親は承認のときに「ありがとう」を送る。承認されると画面に落下物が降り、まれにレア・SRが出て「ずかん」に集まる（ガチャ要素）
- 親が設定すると、残高に毎月「りそく」が付く（ふくり）。「ちょきん計算き」で5年後まで見える
- 親は Google アカウント、子供は4桁PIN（またはGoogleアカウント）でログインする
- **マスター**＝その家族のスプレッドシートの持ち主。初期設定を行い、アプリの中から変更・削除できない

## 2. 構成（無料で作れる）

| 部品 | 役割 |
|---|---|
| GitHub Pages | 画面（HTML/CSS/JS の静的ファイル）。全家庭で共通 |
| Google スプレッドシート | データ保存。**家庭ごとに1つ**（各家庭の親のドライブ） |
| Google Apps Script（スプレッドシートにバインド） | JSON API。ウェブアプリとして「自分として実行・全員がアクセス可」で公開 |
| Google OAuth（IDトークン） | 親のGoogleログインの本人確認 |

- 画面は接続先（家庭ごとのApps ScriptのURL）を URL パラメータと端末に保存して使う。共有QRコードにも接続先が入る
- 通信は `text/plain` の POST（CORSの事前確認が起きない形）で JSON をやり取りする
- 日付を含むデータは文字列にしてから返す（Apps Script の `google.script.run` は Date を返すと結果全体が null になるため、v2 ではこれが原因で履歴や承認待ちが表示されなかった）
- 書き込みはスクリプトロックで直列化し、ボタン1回ごとに付ける一意のIDで二重登録を防ぐ
- 子供の画面は2段階で読み込む：①残高・お手伝いボタン・りれき（最新N件）・カレンダー用の軽い一覧・ずかん → 表示 → ②ボーナス発生中・月初ボーナス・定期おこづかい・りそくの判定（記録が1000件を超えても最初の表示を待たせないため）
- レア落下物の図鑑（100種の絵文字・名前・うんちく）は画面側のファイル（`rares.js`）に持ち、サーバーは番号（0〜99）だけを扱う

## 3. 画面

### 3.1 ログイン画面（子供・親で共通）

上から順に：
- アプリ名
- PIN入力の丸（4つ）
- **キーパッド 4行×3列**：`1 2 3 / 4 5 6 / 7 8 9 / 削除 0 ログイン`
  - 1つのキーは正方形。スマホでは画面幅と高さに合わせてバランスよく縮み、PCでは幅320px程度で止まる
  - PCのキーボードの数字・Backspace・Enterでも操作できる
- 「Googleでログイン」ボタン
- 「初期設定」ボタン（未設定・シート破損時のみ表示）
- 「共有QRコード」（押すと開く。接続先の変更もここから）とバージョン表記

ログアウトすると必ずこの画面に戻る。ログイン画面の要素は子画面・親画面には出さない（共有QRのタブは廃止）。

PINは端末（ブラウザ）単位で失敗回数を数え、3回で1分、6回で5分、10回で完全ロック。ロック中は正しいPINでも「ちがいます」とだけ表示する。完全ロックは、その端末で親がGoogleログインするか、親の設定タブで解除する。

### 3.2 子画面（タブ：ざんだか／おてつだい／カレンダー／ずかん）

**上部**
- 自分の名前（⚙付き）を押すと「じぶんのばんごう」画面へ。キーパッドで新しい4桁を2回入力し、一致したときだけ変更。変更後「あなたが変更した番号は○○○○です」を表示し、OKで完了（兄弟と同じ番号は使えない）
- 最後に開いたタブを端末に覚えておき、次に開いたときはそのタブから始まる（初回は「ざんだか」）

**ざんだか**（お金の出入り）
- 残高
- りそくカード（親がりそくを設定したとき、または過去にりそくを受け取ったことがあるときだけ）
  - 「毎月○% ふえる」、りそくでふえた合計、残高のうち「じぶんでためた分」と「りそく」の割合のバー、月ごとの実績（直近6か月）
  - 「つかわなければ、今月末に +○円 ふえるよ（○円 × ○%）」
  - 受け取っていない月があれば「りそくがついたよ！」と「うけとる」ボタン（たまっている月の分をまとめて受け取る）
- 「おこづかい発生中」（定期おこづかいの支給日を過ぎて、まだ受け取っていない月があるときだけ）。押すたびに古い月から1か月分を受け取る
- 「ボーナスを確認」（未処理の月初ボーナスがあるときだけ）
- 受け取れるおこづかい・ボーナス・りそくがあるときは、タブ名「ざんだか」に●を付ける（ほかのタブにいても気づけるように）
- つかったきろく（金額・内容）。押した瞬間に入力欄を空にし、ボタンを数秒押せなくする
- ちょきん計算き（4.7）
- りれき（お金の出入り）：お手伝い以外の記録（つかった・おこづかい・ボーナス・りそく・残高調整）を新しい順に**最新N件**（N＝設定の「りれきの表示件数」、初期値30）

**おてつだい**
- 残高（小さく）
- 「ボーナス発生中」表示（お手伝いボタンの上）：昨日まで2日続けてお手伝いしている日、今日すでに2回した日（設定で無効にしたボーナスは出ない）
- お手伝いボタン（名前と金額）。押すと**確認画面**（「○○（30円）おくる？」）が出て、「おくる」を押したときだけ送る（スクロール中の誤タップ対策。やめる・画面外タップ・Escはすべてキャンセル）。送ったボタンは3秒ほど暗くなって押せない。送った瞬間に小さな紙ふぶき
- 「家族で1日○回まで」（4.8）が決まっているお手伝いは、ボタンに「家族であと○回」と出し、上限に達するとグレーにして「きょうは しょう がやったよ」（自分なら「じぶん」）と出して押せなくする。並び順は変えない
- 1日の上限（3回）に達すると「親に追加をおねがいする」を表示
- おてつだいのりれき：お手伝いと「上限追加のおねがい」を新しい順に**最新N件**

**りれき共通**
- 申請中・承認済み・却下を表示。それより前はカレンダーの日付から見られる
- **自分が押した申請中のもの**は「取り消す」ができる（取り消したものは自動で非表示）。親が承認したあとは取り消せない
- 自分が押した申請中のお手伝いは「日付を直す」で、やった日（月日）を直せる（メモに「（名前）編集済み」）
- 承認済み・却下の記録には、最後に承認／却下した人の名前を出す
- 承認済みのお手伝いには、親からの「ありがとう」を💌で出す
- 押した直後は通信を待たずに画面へ仮表示し、あとでサーバーの内容に置き換える（固まって見えないように）

**おいわい**（子供本人が開いたときだけ。親が子の画面を開いたときは出さない）
- 前に見たときから、承認されたお手伝い・受け取ったボーナス・おこづかいがあれば、1件につき5この落下物（4.6）を降らせ、そのあとでカードを出す
  - カード：承認されたお手伝い（＋金額）と親の「ありがとう」、出たレア・SR（はじめてなら「NEW!」、確定開きなら「🔓確定開き」）。レアの行を押すとうんちくが読め、とじるとカードにもどる
  - 題名：ふつうは「しょうにんされたよ！」、ボーナスだけなら「ボーナスをうけとったよ！」、おこづかいだけなら「おこづかいをうけとったよ！」、レアが出たら「レアが出た！」、SRなら「SRが出た！！」
- 落下物のはずれは色つきの四角。レア・SRが出たときは、落ちはじめて約1秒で全体を**一時停止→暗転→レアだけ大きくなって点滅**（レア約2.2秒・SR約3秒。画面をタップで飛ばせる）してから再開し、落ちきってからカードを出す
- 見たものは端末に覚えておく。はじめてその端末で開いたときは、今までの分はおいわいしない
- 端末の「視差効果を減らす」などの設定がオンなら、動きのある演出はせずカードだけ出す

**カレンダー**
- 月曜始まり。初期表示は今月。前の月へ移動でき、今月までは戻れる。未来の月へは進めない
- 日を開かなくてもわかる印（申請中と承認済みの記録で判定。却下・取消は数えない）
  - 背景色：お手伝いした日（回数も表示）。1日3回以上の日は別の色
  - 赤い枠：お金をつかった日
  - 青い「＋」：お金がふえた日（おこづかい・ボーナス・プラスの残高調整）
  - オレンジの「・」：申請中の記録がある日
- 印は全期間の記録で付ける（りれきの表示件数とは関係ない）
- 日付をタップすると、その日の記録（お手伝い・お金の出入りの両方）を一覧表示（りれきに出ていない古い日は、その日の分だけサーバーから取る）

**ずかん**（4.6）
- 見出しに「○ / 100（SR ○ / 10）」と「きょうだいだけ ○」
- 確定開き：使えるときは「確定開きを使う」ボタン、使ったあとは「じゅんびOK！」、今月使ったあとは「来月1日にまた使えるよ」、レアがぜんぶそろったら「SRはじぶんの運でさがそう」
- 10×10のマス（0〜99番。下の1列がSR）。持っているものは絵文字（2こ以上なら数）、兄弟だけが持っているものは黒いシルエット、だれも持っていないものは「？」
  - マスを押すと：持っている→名前・レア度・持っている数・うんちく／兄弟だけ→シルエット・レア度・「○○ が見つけているよ！」（名前とうんちくはひみつ）／だれも→「？？？」とレア度
- 落ちる数と確率の説明
- レアが出たのに「ずかん」タブを見ていないときは、タブ名に●を付ける

### 3.3 親画面（タブ：承認待ち／ユーザー／設定）

**承認待ち**
- 上：申請中の一覧（古い順）
- 下：全員分のりれき（申請中以外）を**記録の日付の新しい順に最新3件だけ**（ボーナスは確定した日ではなく翌月1日の位置に並ぶ。システム承認なので承認待ちには出ない）。それより前の記録は「ユーザー」→「子の画面へ」で見る・直す
- 親のボタン（親に「取り消す」はない。間違いは却下で直す）
- **非表示にした記録は、承認・却下を切り替えられない**（却下→非表示→通信の遅れを使って再承認、のような「隠れたまま残高に入る」操作を防ぐ）
- 承認⇔却下を何度切り替えても、記録に残すのは**最後に決めた人と結果だけ**（メモに「却下」「再承認」の履歴を積み上げない）

  | 状態 | ボタン |
  |---|---|
  | 申請中 | 承認・却下・編集 |
  | 承認済み（ボーナス含む） | 却下・編集 |
  | 却下 | 承認（再承認）・非表示 |
  | 取消（子供が自分で取り消したもの） | 非表示 |

- 編集：項目名・金額・日付（月と日のみ。年と時刻は元のまま、未来日は不可）。申請中・承認済みでできる。メモに「（親の名前）編集済み」を追記
- お手伝いの「承認」を押すと「ありがとう」の画面が出る：スタンプ6種（ありがとう！／たすかったよ！／さすが！／ピカピカだね✨／いつもえらいね／またおねがいね）か、自由なひとこと（40文字まで）。**何もえらばずに承認すると、スタンプのどれかをランダムで送る**。再承認でえらばなかったときは前の「ありがとう」のまま

**ユーザー**
- 一番上にログイン中の親の名前（マスターなら「（マスター）」）
- 子供の一覧（残高付き）。各子供に「子の画面へ」
- ほかの親の一覧（表示だけ。マスターは「（マスター）」）
- 一覧には編集ボタンを置かない。**編集は一番下の「ユーザー変更」で相手を選んで行う**（マスター以外の親は編集・無効化できる）
- 「ユーザー変更」フォーム：新規追加／既存ユーザーの名前・役割・メール・PIN・有効無効を変更。子供を編集するときは**今のPINを表示**する（子供が自分で変えた番号も親が確認できる）。マスター本人が自分を選んだときは表示名だけ変えられる
- マスターのメールアドレスはUsersに登録できない（マスターは最初から親として扱われる）

**子の画面（親が開いたとき）**
- 子画面と同じ見た目に加えて、「← 親の画面へ戻る」「残高調整（マイナス可）」
- お手伝いボタンを親が押せる。確認画面で「記録する」を押すと「その親が承認済み」として記録（上限なし）
- 「おこづかい発生中」「ボーナスを確認」も親がここで押せる
- 「お手伝い編集」で編集モードになり、ボタンの名前・金額・**家族で1日何回まで**（0＝上限なし）の変更、追加、削除ができる（削除は非表示にするだけで過去の記録は残る）
- 「りそく」の「うけとる」、ずかんの「確定開きを使う」も親がここで押せる（おいわいの演出は子供本人の端末でだけ出る）
- りれきのボタンは承認待ちタブと同じ（申請中＝承認・却下・編集／承認済み＝却下・編集／却下＝承認・非表示）

**設定**
- スプレッドシートへ移動
- アプリ名とアイコン（絵文字＋背景色）の変更。変更後に作ったホーム画面のショートカットに反映
- ボーナス：「1日3回目から」「3日連続」をそれぞれ有効／無効にできる
- 定期おこづかい：有効／無効、金額、毎月の支給日（1〜31。その月に無い日は月末）、開始年月
- りそく：付ける／付けない、月の%（0.1〜20）（4.5）
- りれきの表示件数（5〜500、初期値30）
- PINをまちがえた端末：**1度でもPINを間違えた端末だけ**を表示（失敗0回の端末は出さない）。「解除する」（ロック中のみ）「非表示」ボタン。非表示にしても、その後また間違えると再び表示される。端末情報が30件を超えたら、失敗したことのない端末→非表示にした端末の古い順に黙って削除（一覧に出ている端末は消さない）
  - 一覧に端末があるときは案内を出す：「配ったばかりのころは子供のいたずらや押しまちがいでも出る。使い始めてしばらくたってから心当たりのない失敗が出たら、URL（共有QR）がもれている可能性があるので、新しいデプロイでURLを変え、古いデプロイをアーカイブして、共有QRを配り直す」（手順はREADME「URLがもれたかもしれないとき」）
- 全体のPINロック（端末を変えながらの総当たり対策）が働いているときは、その表示と「全体ロックを解除する」
- 初期設定（シートの修復）：足りないシート・列を作り直し、重複したお手伝いIDなどを直す。データは消さない

## 4. ルール

### 4.1 記録の種類と状態

| 種類 | 作られ方 | 最初の状態 |
|---|---|---|
| お手伝い | 子供が押す／親が押す | 子供＝申請中、親＝承認済み |
| つかった | 子供／親が入力 | 子供＝申請中（ただし残高からはすぐ引く）、親＝承認済み |
| 残高調整 | 親が入力 | 承認済み |
| 上限追加のおねがい | 子供が押す（1日1回） | 申請中。承認されるとその日は上限なし |
| 月初ボーナス | 「ボーナスを確認」 | 承認済み（承認者は「システム」） |
| 定期おこづかい | 「おこづかいをうけとる」 | 承認済み（承認者は「システム」）。日付はその月の支給日 |
| りそく | 「うけとる」（りそくカード） | 承認済み（承認者は「システム」）。日付はその月の翌月1日。子供は取り消せない |

状態：申請中 → 承認済み／却下。承認済み ⇔ 却下 は親が何度でも入れ替えられる（非表示にしたものは除く）。子供は自分が押した申請中のものを取消にできる。
残高は「承認済み」の金額と「申請中のつかった」の合計で計算する。却下・取消は30日後に自動で非表示（削除はしない）。

### 4.2 取り消しできる人

- 子供：**自分が押した／入力した申請中の**お手伝い・つかった・おねがい。親が承認したもの、親が入れたもの、ボーナス、おこづかい、残高調整は取り消せない。取り消したものは自動で非表示
- 親：「取り消す」は使わない。すべて「却下」で直す（却下後に「承認」で戻せる、「非表示」で隠せる）

### 4.3 月初ボーナス

- お手伝いを押した時点では基本金額のみ。ボーナスは翌月にまとめて計算する（あとから取り消されたり、承認が取り消されたりするため）
- 子供（または親が子の画面）を開いたとき、**お手伝いをした過去の月でボーナス処理がまだの月**があれば「ボーナスを確認」を表示。押すと月ごとに1行ずつ記録する
  - 日付：その月の翌月1日
  - 項目：「○月ボーナス」、メモ：「○月ボーナス ○円（内訳）」
  - 0円でも記録する（処理済みの印になる）。親が却下しても処理済みのまま
  - 2か月以上たまっていれば、その月数分の行ができる
- 計算対象：その月の「承認済み」のお手伝いだけ（却下・取消は数えない）
  - 同じ日の3回目以降のお手伝い：1回につき +10円
  - 3日以上連続した日（前月からの連続も数える）のお手伝い：1回につき +10円
  - 両方当てはまれば両方加算
- **その月に承認待ちのお手伝いが1件でも残っている間は、その月のボーナスは計算・確認できない**。子供の画面には「承認待ちが○件あるので、親の承認のあとで確認できるよ」と出し、親が承認か却下をして0件になると「ボーナスを確認」が押せるようになる
- 「ボーナス発生中」の表示は、押した直後にわかるよう申請中も含めて判定する（目安の表示）
- 親は承認不要で入るボーナスを、承認済みの記録と同じく「編集」（金額修正、メモに編集済みが残る）または「却下」できる
- 設定でボーナスを無効にすると、その種類は0円で計算する。両方無効のあいだは「ボーナスを確認」自体を出さない。両方無効から有効に戻したときは、その月から計算する（止めていた間の月をさかのぼって出さない）

### 4.4 定期おこづかい

- 設定：有効／無効、金額、毎月の支給日、開始年月
- 開始年月から今月までの各月で、**支給日（その月に無い日は月末）を過ぎていて、まだ受け取っていない月**があれば、子供の画面に「おこづかい発生中」を出す
- 「おこづかいをうけとる」を押すたびに、古い月から1か月分を記録する（数か月分たまっていれば、その回数押せる）
  - 日付：その月の支給日、項目：「○月のおこづかい」、承認者：システム
  - 受け取った月は印が付き、あとで支給日を変えても同じ月に2回目は出ない
- 親は承認済みの記録と同じく「編集」「却下」できる

### 4.5 りそく

- 親が設定タブで「付ける」と「月の%（0.1〜20）」を決める。付けない→付けるにした月から付き始める（さかのぼらない）。%を変えると、まだ受け取っていない月にも新しい%が使われる
- 毎月、**月末（翌月1日0時より前）の残高 × %** を切り捨てて、その月のりそくにする（0円の月は出さない）。残高は承認済み＋申請中のつかった（4.1と同じ）
- 子供の画面の「うけとる」で、たまっている月の分をまとめて受け取る。1か月1行、日付は翌月1日、項目は「○月のりそく」、メモに「○円 × ○%」
- **ふくり**：受け取ったりそくは次の月の残高に入る。受け取っていない月のりそくも、次の月の計算では残高にふくめる（受け取るのが遅れても損をしない）
- りそくは本物のお金（親が払う）。親は承認済みの記録と同じく「編集」「却下」できる

### 4.6 レア落下物・ずかん・確定開き

- **落ちる数**：承認されたお手伝い（親が代わりに記録したものも）・受け取った月初ボーナス・定期おこづかい 1件につき5こ。りそく・つかった・残高調整では落ちない
- **確率**（1こごと）：SR 1/1000、レア 1/100、それ以外ははずれ。レアの中は ★1（45種）：★2（30種）：★3（15種）が 3：2：1 の出やすさ。SRは10種で同じ出やすさ
- **どれが落ちるかは記録のIDだけで決まる**。読み直しても、1件ずつ承認してもまとめて承認しても、却下して再承認しても同じ（引き直しはできない）。承認済みでなくなった記録の分は図鑑から消える
- 図鑑は、その子供の承認済みの記録で落ちたものの合計。兄弟（有効な子供）が持っているものはシルエットで見える
- **確定開き**：子供ごとに**月に1回**（使わなかった月の分は持ち越さない）
  - 使うと「じゅんびOK」になり、**そのあとに承認された対象の記録の1こ目**が「まだ持っていないレア（★1〜★3。SRは対象外）」になる。何が出るかはそのときに決まり、保存される（あとで図鑑が増えても変わらない）
  - その記録が却下されたら確定はとりけされ、「じゅんびOK」にもどる（次の承認で出直す。中身は変わることがある）
  - レアが90種ぜんぶそろっていると使えない
- お試し用に、スクリプトプロパティ `DROP_TEST_BOOST`（何倍）で確率を上げられる（ふだんは空）

### 4.7 ちょきん計算き

- 1回の金額（お手伝いの金額から選ぶ。初期値はいちばん多い金額）と1日の回数（1〜3回）を選ぶ
- **1か月（30日）ぶんを式で表示**：「30円 × 3回 × 30日」「3回目ボーナス 10円 × 1回 × 30日」「3日連続ボーナス 10円 × 3回 × 28日（3日目から）」→「1か月で ○円」。設定で無効にしたボーナスは出さない
- **5年の棒グラフ**：いまの残高から、毎月その金額をためて1円も使わず、月末にりそく（親の設定の%、切り捨て）が付いたとしたときの1〜5年目の残高。棒は「じぶんでためた分」と「りそく」の2色。下に「5年後 ○円（そのうち りそく ○円）」。りそくが付いていないときは「親が設定するとふえるよ」

### 4.8 家族で1日○回まで

- お手伝いごとに「家族（兄弟みんな）で1日何回まで」を決められる（0＝上限なし）。今日の回数は、申請中と承認済みの全員分で数える
- 上限に達したお手伝いは、子供は押せない（サーバーでも断る）。親が子の画面で代わりに記録するときは止めない
- 新しく作る家庭の初期値：食器洗い・ペットのお世話は2回、ほかは1回。v3.2以前から使っている家庭は、修復で列が追加されるだけで上限なし（必要なら親がお手伝い編集で設定する）

### 4.9 二重押し・処理落ち対策

- すべての書き込みボタンは押した後数秒押せない（暗く表示）
- 同じ操作が2回サーバーに届いても、1回分しか記録しない
- 画面は先に仮表示し、通信が遅くても操作を続けられる
- 通信は45秒でタイムアウトし、エラーを画面下に表示する

## 6. セキュリティの考え方

- マスター＝スプレッドシートの持ち主。初期設定（シート作成）はマスターのGoogleアカウントでしかできない。マスターはUsersシートに入れず、アプリの中から変更・削除・無効化できない（表示名だけ本人が変えられる）
- 旧版でUsersにあったマスターの行は、初期設定（修復）のときにIDと表示名を引き継いでUsersから外す（過去の記録はそのまま）
- GoogleのIDトークンは、発行先（クライアントID）・発行元・メール確認済み・使い捨ての値（nonce）を検証する
- すべての操作はサーバー側でも権限を確認する（子供は自分の記録だけ、親専用の操作は親だけ）
- 個人情報（メール・PIN・スプレッドシートID・URL）はリポジトリに置かない

## 8. QA抜粋

### Q1. Webからの完全自動セットアップはできない

- **要望**：最初の親がログインするだけで、スプレッドシート作成・スクリプト入力・初期化まで Web からすべて行う
- **制約**：GitHub Pages のページから他人のドライブにスクリプト付きスプレッドシートを作る・ウェブアプリとして公開するには、Apps Script API と Drive の「制限付き／機密」スコープが必要。これらは Google の審査（セキュリティ評価を含む場合あり、数週間〜）を通さないと一般公開できない。また、ウェブアプリの公開と権限の承認は、最後に持ち主本人が Apps Script の画面で行う必要がある
- **今の実装**：①原本スプレッドシートを「コピー」（ボタン1つ）②Apps Script で「デプロイ」（数クリック）③URLを貼り付け ④「初期設定」ボタン → シート作成・最初の親の登録は自動。README に手順を記載
- **決定**：「原本コピー＋デプロイだけ手作業」で進める（Googleの審査は受けない）

### Q2. OAUTH_CLIENT_SECRET は不要になった

- **要望**：`OAUTH_CLIENT_ID` と `OAUTH_CLIENT_SECRET` をスクリプトプロパティで管理
- **実装**：画面が GitHub Pages に移ったため、Google から直接IDトークンを受け取る方式に変更。シークレットは使わない（ブラウザに置けない値なので、むしろ無い方が安全）。`OAUTH_CLIENT_ID` はスクリプトプロパティで上書き可能、未設定なら共通のIDを使う
- **決定**：管理者のクライアントIDを全家庭で共用する。他の家庭が使い始める前に、OAuth 同意画面の「ブランディング」を完成させ「本番環境」に公開する（ログイン時に管理者のアプリ名・サポート用メールが表示される）

### Q4. ボーナス計算に「申請中」は含めない

- ボーナスはシステムが承認するので、計算は「承認済み」のお手伝いだけ
- 対象の月に承認待ちのお手伝いが残っていれば、その月のボーナスは計算しない（確認できない）。親が承認・却下を済ませてから確認する
- 確定後に直したい場合は、親が履歴からボーナス行を「編集」（承認済みと同じ操作。メモに編集済みが残る）
- 補足：月をまたぐ3日連続は前の月の承認済みの日も数える。前の月に承認待ちが残っていると、次の月の月初の連続日数が少なく数えられることがあるので、月ごとに順番に承認を済ませるのがおすすめ

### Q13. 親のボタンの整理

- 親の「取り消す」は廃止（承認待ちから消えてしまうため）。承認待ち＝承認・却下・編集／承認済み＝却下・編集／却下＝承認・非表示
- 子供が自分で取り消した記録（取消）は、v3.0.7 から取り消した時点で自動で非表示になる
- 却下の記録は編集できない（直したい時は先に承認してから編集）

### Q5. ボーナスの数え方

- 「1日3回目」＝同じ日の3回目以降のお手伝い1回ごとに +10円（4回目も+10円）
- 「3日連続」＝連続3日目以降の日のお手伝い1回ごとに +10円。月をまたいだ連続も数える
- 「ボーナス発生中」は、昨日まで2日連続している日（今日すると3日目）と、今日すでに2回した日に表示

### Q6. 1日の上限（3回）と「追加をおねがいする」は残した

- 指示になかったため v2 の仕様を維持。親が子の画面で押す分は上限なし

### Q7. 子供が取り消せる範囲

- v3.0.7 で変更：子供が取り消せるのは、自分が押した／入力した**申請中のもの**だけ（親が承認したあとは取り消せない）。取り消したものは自動で非表示。親が押したもの・ボーナス・おこづかい・残高調整は子供は取り消せない。親は取り消しではなく却下を使う（Q13）

### Q10. 共有QRコードをログイン画面に置く

- ログイン前でも見られるが、QRに入っているのは「アプリのURL＋接続先」だけで、使うにはPINかGoogleログインが必要。問題があれば親画面に戻す

### Q12. 子供が日付を直せる範囲

- 子供は「自分が押した」「申請中」の「お手伝い」の日付（月日）だけ直せる。承認後は親だけが直せる（承認済みの日付を子供が動かすとボーナスや親の確認と食い違うため）
- 承認後も子供に直させたい場合は教えてください

### Q14. マスター（持ち主）の扱い

- マスター＝そのスプレッドシートの持ち主のGoogleアカウント。初期設定はマスターだけができる
- Usersには入れない。「ユーザー」タブでは親の一覧の先頭に「（マスター）」として出し、変更・削除・無効化はできない。表示名だけはマスター本人が変えられる
- マスターがいるので「親が0人になる」制限は不要になった（ほかの親は自由に無効化できる）

### Q15. りれきの「最新Ｎ件以降は自動非表示」

- **表示だけを最新N件にする**（Nは設定、初期値30）。記録に「非表示」の印は付けない
- 理由：非表示の印を付けると、Q16のルールで承認・却下を二度と変えられなくなるため。古い記録はカレンダーの日付から見て、直すこともできる
- 親の承認待ちタブの下のりれきは、ご指示どおり最新3件だけ、入力直後の物を変更しやすいように

### Q16. 非表示にした記録は承認・却下を変えられない

- 親が「非表示」にした記録（却下・取消の30日後の自動非表示も含む）は、承認・却下・再承認のボタンを出さず、サーバー側でも受け付けない

### Q17. PINをまちがえた端末の一覧と、30件の自動削除

- 「1度でも失敗した端末は親が非表示にしない限り残る」を優先し、端末情報が30件を超えたときに消すのは、失敗したことのない端末→親が非表示にした端末（古い順）だけにした
- そのため、多数の端末から間違え続けられると30件を超えて残ることがある（全体のPINロックで失敗の回数自体は抑えられる）

### Q18. お手伝いボタンの誤操作対策

- 押すと確認画面が出て「おくる」を押したときだけ送る（やめる・Esc・画面外はキャンセル）

### Q19. 子供の番号（PIN）を親に表示すること

- 以前は「PINはアプリ上に表示しない」方針だったが、ご指示により、親が「ユーザー変更」で子供を選ぶと今の番号を表示するようにした（親だけに見える）
- 子供が番号を変えるとき、兄弟と同じ番号は「つかえないよ」と断る。このため、何度も試すと兄弟の番号を推測できてしまう点は残る（家庭内の利用なので許容）

### Q20. 定期おこづかいとボーナスの設定の扱い

- 定期おこづかいは、開始年月からの各月について、その月の支給日を過ぎたら出る。開始年月より後に登録した子供にも、開始年月からの分が出る（出したくない月は、親が受け取ったあとに却下する）
- 1度受け取った月は、支給日や開始年月を変えても2回目は出ない
- ボーナスを両方無効にしたあと有効に戻すと、その月から計算する（止めていた間の月はさかのぼらない）

### Q21. 子供の画面の3タブ（こう実装）

- 「上限追加のおねがい」はお手伝いに関係するので「おてつだい」側、月初ボーナスとおこづかいは「お金がふえる」ので「ざんだか」側に入れた
- タブが分かれたことで「おこづかい発生中」「ボーナスを確認」に気づきにくくならないよう、受け取れるものがあると「ざんだか」タブに●を付けた
- お手伝いボタンを押すまでタップが1回増えないよう、最後に開いたタブを端末に覚えておく。「おてつだい」タブにも残高を小さく出す
- りれきの表示件数Nは、タブごとに最新N件（お手伝いが多くても、お金のりれきが押し出されない）

### Q22. 心当たりのないPIN失敗の案内

- 設定タブの「PINをまちがえた端末」に端末が出ているときだけ案内を表示する（常に出すと見慣れて読まれなくなるため）
- URLを変える手順（新しいデプロイ→古いデプロイをアーカイブ→共有QRを配り直す→ホーム画面のショートカットを作り直す）はREADMEに記載。データとログイン状態はそのまま使える

### Q24. ちょきん計算きの前提

- 期間ボタン（1週間／1か月／1年）はやめて、式は1か月ぶんだけ、その下に5年の棒グラフ（ご指示）
- 「いまの残高から、毎月同じだけためて、1円も使わない」前提。3日連続ボーナスは毎月「3日目から」で計算する（前の月からの連続は数えない、少なめの見積もり）
- りそくは親が設定した%を使う。設定がなければりそくなしで計算し、「親が設定するとふえるよ」と出す（子供が%を選んで試すことはできない）

### Q25. レアの出る確率とコンプリートまでの目安

- 1日10回承認される子供（お手伝い3回＋その他）で、全100種そろうのは平均約4年。確定開き（月1回・SRは対象外）があるので、実際は平均約1.5〜2年（シミュレーション）
- 最後まで残りやすいのは★3（1種あたり約2万1千こに1こ）。SRは確定開きの対象外なので、最後まで運しだい
- 1件ずつ承認してもまとめて承認しても確率は同じ（記録ごとに決まる）。同時に2こ以上レアが出ることもある（5件まとめて承認で約3%）

### Q26. 確定開きの細かいルール

- 月に1回、子供が押して使う（ポイントなどは使わない）。押した時点では何が出るかわからず、次に承認されたときに暗転の演出で出る
- 確定したお手伝いが却下されたら「じゅんびOK」にもどり、次の承認で出直す（中身は変わることがある）。今月の1回は使ったまま
- 親が子の画面から代わりに使うこともできる

### Q27. りそくは本物のお金

- 月1%でも年に約12.7%（ふくり）。残高が多い家庭では親の負担が大きくなるので、設定の説明に「払える範囲の%に」と書いた
- オンにした月から付き始める（それより前の月にさかのぼらない）。受け取るのを忘れていても、受け取ったときに前の月の分もふくりで計算される
